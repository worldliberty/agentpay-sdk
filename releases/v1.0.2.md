# AgentPay SDK version 1.0.2 release notes

**Release date:** 2026-11-23
**Current version:** v1.0.2

These notes cover what changed in AgentPay SDK `v1.0.2` relative to `v1.0.0`. Version 1.0.1 was
prepared but never published; its changes are included here. For the 1.0.0 rewrite, see the
[v1.0.0 release notes](./v1.0.0.md).

## Release summary

AgentPay SDK `v1.0.2` fixes the installer on older Macs, gives a new wallet limits on every
built-in token so setup no longer asks about each ETH row, fixes MPP charges after a session
through the paying proxy, and sends usage analytics after a random delay instead of every 30
seconds. Upgrading keeps the wallet, limits, and configuration; there are no API or command
changes (API `1.1.0`).

## Fixed

- **Installer on older macOS:** no more "option -r not recognized" or `xattr` usage text. Older
  `xattr` builds have no `-r` and print their usage error to stdout; the quarantine step is now
  silent and falls back to one file at a time
- **Setup limits:** ETH has recommended limits like every other built-in token (0.005 per payment,
  0.05 a day, 0.35 a week, about $15 / $150 / $1,000), so a new wallet starts with limits on every
  built-in token and the limits step continues at once. Existing configurations get the ETH
  recommendation once; limits you set are unchanged. Tokens you add without a recommendation
  still ask for a limit
- **MPP charges after a session:** a persisted session channel no longer blocks one-time charges
  through the paying proxy (for example with `agentpay proxy start --network solana-mainnet`
  against a merchant where a Tempo session was opened earlier)

## Changed

- **Telemetry timing:** usage analytics go out in batches after a random delay of up to an hour
  from a batch's first event, instead of every 30 seconds. Pending events are sent when the
  service stops; crash and error reports are still sent at once
- **Version on reports:** analytics carry Mixpanel's `$app_version_string` next to
  `service_version`; Sentry reports keep the `agentpay-paymentd@<version>` release
- **Installer asset:** the release carries the installer as both `install.sh` and `installer.sh`,
  so `curl -fsSL https://wlfi.sh | sh` keeps installing the latest release

## Upgrading

Run the installer again and let setup restart the services:

```sh
curl -fsSL https://wlfi.sh | sh
agentpay setup
```

`agentpay setup` keeps the existing wallet. See the [changelog](../CHANGELOG.md) for the full list.
