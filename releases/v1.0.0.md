# AgentPay SDK version 1.0.0 release notes

**Release date:** 2026-11-08
**Current version:** v1.0.0

These notes cover what changed in AgentPay SDK `v1.0.0` relative to `v0.5.0`. The `v0.6.0`
development line was never released; its changes are included here.

## Release summary

AgentPay 1.0.0 is a rewrite around two Rust daemons and a small client:

- the **signer daemon** (`agentpay-daemon`, root) keeps keys, policies, spending limits, manual
  approvals, and nonces;
- the **payments service** (`agentpay-paymentd`), running as an unprivileged service account, does
  all network work (chains, x402, MPP, the paying proxy, balances, funding) and asks the signer
  daemon for every signature as the calling agent;
- the **`agentpay` client** (TypeScript + Ink) is the command line and terminal UI. It contains no
  payment logic.

There is no vault password any more. The signer daemon's state is encrypted under a machine secret
only root can read, and admin actions are approved with Touch ID or the Mac password (a Secure
Enclave key) on macOS, or with `sudo`. The daemons speak a documented, versioned API (API `1.1.0`,
[docs/daemon-api.md](../docs/daemon-api.md)) that third-party clients can use directly.

## What's new

### Setup

- `curl -fsSL https://wlfi.sh | sh`, then `agentpay setup`. The new installer verifies the release
  tarball against `SHA256SUMS`, installs into `~/.agentpay` without sudo, and needs no Node.js or
  Homebrew
- `agentpay setup` installs both services with one sudo prompt (`agentpay-setup install`), then runs
  a guided wizard: create, restore, or keep a wallet; turn on Touch ID; set spending limits; export
  an encrypted backup
- `sudo ~/.agentpay/bin/agentpay-setup status` and `… uninstall [--keep-state]`

### Spending limits and approvals

- limits per network and asset: per payment, rolling 24 hours, rolling 7 days
- deny by default: an asset without a limit cannot be spent, and setup makes every seeded asset
  either limited or blocked
- `agentpay admin limits` (interactive) and
  `agentpay admin limits set <asset> --network <net> --per-tx … --daily … --weekly … [--exclude]`
- `agentpay admin approvals`, `agentpay admin approve <id>`, `agentpay admin reject <id>`
- payments with `--broadcast` wait for an approval (`--approval-wait`, 300 seconds by default);
  `agentpay resume --approval-request-id <id>` finishes one that returned before the decision
- `agentpay admin touch-id enable|status|disable`

### Payments

- EVM: `transfer`, `transfer-native`, `approve`, `broadcast`, `sign-typed-data` on any configured
  chain (BSC, Ethereum, and Tempo built in); USD1 on BSC by default
- Solana: `transfer-sol` and `transfer-spl`, with durable nonces so payments can wait for manual
  approval
- x402: `agentpay x402 <url>` pays x402 v1 and v2 `exact` challenges with EIP-3009
- MPP: `agentpay mpp <url>` pays Tempo charges and TIP-1034 sessions (sessions v2), with persisted
  channels (`--session-key`), deposit caps, currency selection, streamed responses, and
  `--close-session`
- MPP on other chains: `evm` and `arbitrum` charges on any configured EVM network, paid gasless
  when the merchant allows it (EIP-3009 `authorization`, then `permit2`, then `hash` or
  `transaction`), and `solana` charges, including merchant-paid fees and split payments;
  `--network` and `--currency` pick among a merchant's offers
- built-in networks: Arbitrum, Base, Optimism, and Polygon (and the Arbitrum and Base testnets),
  with USDC on every EVM network and on Solana, and USD1 on BSC, Ethereum, Solana, and Tempo
- `examples/sample-llm` shows a third-party tool paying an MPP LLM endpoint through the proxy
- paying proxy: `agentpay proxy start` runs a token-protected loopback proxy that pays `402`
  answers for any HTTP client

### For agents

- every command has `--json`, printing exactly one JSON document, errors included:
  `{"error": {"code", "message", "next_action"}}`
- exit codes: `0` success, `1` failure, `2` usage error, `3` waiting for manual approval, `4` not
  installed or no agent credentials
- `agentpay status --json` reports service, chain, and limit health with warnings
- the skill pack and adapters in `skills/agentpay-sdk` are updated to the new commands

## Removed

- the TypeScript CLI, its npm package and the `./link` export, and the pnpm monorepo
- the vault password and every password prompt
- Railgun private transfers
- the relay and the web approval console
- Stripe Link and Bitrefill (`agentpay link …`, `agentpay bitrefill …`)
- MPP sessions v1 (legacy escrow channels)
- plaintext private key export
- the `agentpay-admin` and `agentpay-agent` binaries, the XPC transport, the Windows TPM backend,
  and the Secure Enclave wallet backend

## Upgrading from 0.5.0

1. Close any open MPP sessions v1 channels with 0.5.0 first; 1.0.0 cannot use or close them.
2. Make sure you have a verified encrypted backup of the wallet.
3. Install 1.0.0 and run `agentpay setup`, choosing **Keep the existing wallet**.

`agentpay-setup` migrates the vault-password install automatically: it creates the machine secret,
re-encrypts the daemon state under it, and only then deletes the stored vault password. If the
migration fails, the state is left unchanged and still opens with the old password. The wallet
and its addresses stay the same. Encrypted backups from earlier releases (formats v1 and v2)
restore through the setup wizard.

Command changes for scripts and agents:

| 0.5.0 | 1.0.0 |
|---|---|
| `agentpay admin setup` | `agentpay setup` |
| `agentpay admin setup --reuse-existing-wallet` | `agentpay setup`, "Keep the existing wallet" |
| `agentpay admin setup --restore-wallet-from <path>` | `agentpay setup`, "Restore from a backup" |
| `agentpay admin tui` | `agentpay` (home) or `agentpay admin limits` |
| `agentpay admin list-manual-approval-requests` | `agentpay admin approvals` |
| `agentpay admin approve-manual-approval-request --approval-request-id <id>` | `agentpay admin approve <id>` |
| `agentpay admin reject-manual-approval-request --approval-request-id <id>` | `agentpay admin reject <id>` |
| `agentpay admin resume-manual-approval-request --approval-request-id <id>` | `agentpay resume --approval-request-id <id>` |
| `agentpay mpp … --amount 0.01` (whole units) | `agentpay mpp … --amount 10000` (base units) |
| `agentpay mpp … --session-state-file <path>` | `agentpay mpp … --session-key <name>` (the old flag still works) |
