# AgentPay SDK version 0.4.0 release notes

**Release date:** 2026-05-07
**Current version:** v0.4.0

These notes cover what is new in AgentPay SDK `v0.4.0` relative to `v0.3.1`.

For managed Linux wallet support, installer compatibility fixes, and CI deduplication changes, see [v0.3.1 release notes](./v0.3.1.md).

## Release summary

AgentPay SDK `v0.4.0` adds the first Solana signing path to the local-first daemon model. This release introduces software-backed Ed25519 vault accounts, Solana wallet metadata throughout setup/status flows, and a structured `agentpay transfer-spl` command for policy-checked SPL token transfers without opening a generic arbitrary-transaction signing surface.

## What's new in v0.4.0

### Solana vault accounts and wallet metadata

- added Solana vault account support backed by software-managed Ed25519 keys
- extended wallet bootstrap, setup, and profile flows to persist and display `solanaPublicKey` and `solanaAddress`
- updated config validation and wallet profile resolution so Solana metadata can be reused across CLI flows

### Structured SPL token transfer support

- added `agentpay transfer-spl` for original-program SPL token transfers through the daemon policy path
- the CLI resolves the fee payer, mint metadata, sender ATA, recipient ATA, and latest blockhash before requesting a signature
- optional `--broadcast` support can submit the signed Solana transaction through RPC and wait for confirmation
- added optional compute budget overrides via `--compute-unit-limit` and `--compute-unit-price-micro-lamports`

### Policy and signing model updates

- extended the domain, signer, policy, transport, and daemon layers to model Solana recipient identities, assets, signatures, and structured SPL transfer actions
- Solana transfers now participate in per-transaction spending policy evaluation instead of bypassing the existing policy system
- manual approval is intentionally unsupported for Solana SPL transfers in this release and fails closed before any approval request is created

### Network and integration updates

- added built-in Solana chain-family support in shared config and network selection logic
- updated relay/web schemas and related CLI plumbing so Solana wallet and transfer data can be represented alongside EVM flows
- added tests covering Solana transfer signing, wallet metadata handling, and policy enforcement behavior
