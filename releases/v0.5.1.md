# AgentPay SDK version 0.5.1 release notes

**Release date:** 2026-10-23
**Current version:** v0.5.1

These notes cover what is new in AgentPay SDK `v0.5.1` relative to `v0.5.0`.

For Fiat payments through Stripe Link, see [v0.5.0 release notes](./v0.5.0.md).

## Release summary

AgentPay SDK `v0.5.1` is a security release. It closes the policy bypasses found in a full review of the codebase. The most serious was in Tempo session signing: the daemon signed a hash that the agent computed, so it never saw what it was approving. The daemon now rebuilds the Tempo transaction and voucher digests from structured fields and checks them against policy before signing. The release also hardens the daemon, the CLIs, the relay and web console, and the installer, and adds crash reporting and usage analytics to the CLI, which can be turned off.

This release has breaking changes. Read [Compatibility and upgrade notes](#compatibility-and-upgrade-notes) before upgrading, and close any open Tempo session channels first.

## What's new in v0.5.1

### Tempo session signing checked by the daemon

- the daemon rebuilds the Tempo session open, top-up, and voucher digests from structured fields and evaluates them against policy, instead of signing a hash precomputed by the agent
- the `agentpay-agent` Tempo session commands take the channel and transaction fields as flags instead of `--signing-hash-hex`
- the daemon tracks which agent key opened each Tempo channel and how much it deposited; vouchers and top-ups are rejected for channels it did not open, for channels opened by another agent key, and for voucher amounts above the deposited total
- Tempo session state files are now v2 and record the channel salt and authorized signer
- MPP challenges must include a `chainId`, and Tempo session challenges must use a pinned escrow contract

### Policy engine

- `BroadcastTx` calldata that the policy engine does not recognize is denied by default
- an `AllPolicies` attachment with zero enabled policies now denies instead of allowing everything
- value-bearing EIP-712 typed data (permits and similar) is denied under `Eip712Signing=Allow` instead of bypassing spend limits
- manual-approval policies no longer mask hard limits; a request that exceeds a hard limit is denied rather than queued for approval
- moving the system clock backwards no longer resets spend budgets
- capped how far a requested nonce may skip ahead of the daemon's tracked nonce, and capped the number of pending manual-approval requests

### Daemon and transports

- hardened admin authentication and lockout
- the encrypted state file now carries a schema version, and its KDF parameters are clamped
- the Unix socket accept loop survives connection errors, and the request body limit is 256 KiB
- the daemon shuts down cleanly on `SIGTERM` and `SIGHUP`, and refuses to start while another daemon holds the lock
- `Debug` output redacts key material
- relay envelopes use `x25519-hkdf-xchacha20poly1305-v2`, which derives keys with HKDF and binds the approval and daemon ids as associated data

### Admin and agent CLIs

- `agentpay admin approve-manual-approval-request` and `reject-manual-approval-request` show the pending request and ask for confirmation; pass `--yes` for non-interactive use
- the admin TUI restores the terminal when it exits
- the decrypted wallet restore key is handed to the Rust admin binary over an inherited pipe instead of a temporary key file
- removed the `--agent-auth-token <value>` argument from the Rust agent; use `--agent-auth-token-stdin` instead, and `AGENTPAY_AGENT_AUTH_TOKEN` is rejected for passthrough commands
- secrets stay off the command line: Keychain writes go through `security -i`, and the relay token is passed over stdin
- child processes get an allowlisted environment, and output read from the Rust binaries is size-capped
- encrypted wallet backups are written in format v2; v1 backups remain readable
- signed Solana transactions are checked before broadcast
- `agentpay private-balance` now exits with code 3 (was 2) when the balance is unavailable, matching the Rust agent's `Unavailable` outcome

### Relay, web console, and RPC

- the relay pins each daemon's public key on first registration and rejects a re-registration that changes it; the web console also pins the daemon's public key
- approval links carry their secret in the URL fragment instead of the query string
- relay cache keys now expire
- the web console uses a nonce-based Content Security Policy
- native balances use the chain's own decimals
- transaction broadcasts are no longer retried
- removing a built-in chain or token from the config now persists

### Crash reporting and usage analytics

- added Sentry crash reporting and Mixpanel usage analytics to the CLI, enabled by default
- added `agentpay telemetry status|enable|disable`, which do not require root access
- telemetry can also be disabled with `AGENTPAY_TELEMETRY=0` or the `DO_NOT_TRACK` convention
- telemetry sends only a random install id, the command, exit code, duration, platform details, bucketed amounts and balances, and scrubbed error text; timestamps are rounded to the minute, and nothing is derived from the wallet address
- Rust signing-binary output is replaced with `<binary> exited <code>` in crash reports rather than scrubbed; wallet and recipient addresses, transaction hashes, RPC URL paths, hostnames, and secrets are never transmitted
- telemetry waits at most 3 seconds at exit and backs off for an hour after a failed delivery

### Installer and release tooling

- the one-click installer verifies the downloaded bundle's SHA-256 against the release digest before extracting it; `SHA256SUMS` is published with every release
- the installer refuses `$HOME`, `/`, `/usr*`, `/opt`, and unrecognized non-empty directories as install or skill-pack destinations
- the minimum supported Rust version is now 1.89
- CI adds lint, typecheck, and Rust MSRV jobs, runs the Rust and JS e2e suites on Linux as well as macOS, and pins GitHub Actions to commit SHAs
- fixed the Linux build of `vault-signer`: the Linux TPM backend now rejects Railgun key creation as unsupported, as the other backends do

## Compatibility and upgrade notes

- **Close open Tempo session channels before upgrading.** Vouchers and top-ups are rejected for channels this daemon did not open, including channels opened before this release or before a daemon reset. v1 Tempo session files are rejected with the channel id, escrow contract, and chain, so the escrowed deposit can be closed and withdrawn before the file is deleted.
- **Upgrade the relay, web console, and daemon together.** The relay envelope format changed to `x25519-hkdf-xchacha20poly1305-v2`.
- **Upgrade every CLI that drives the daemon.** Older CLIs cannot drive Tempo sessions on a `v0.5.1` daemon, and cannot read v2 wallet backups.
- Scripts that approve or reject manual-approval requests without a terminal must pass `--yes`.
- Scripts that pass `--agent-auth-token <value>` or set `AGENTPAY_AGENT_AUTH_TOKEN` must switch to `--agent-auth-token-stdin`.
- Scripts that check for exit code 2 from `agentpay private-balance` must check for exit code 3.
- Source installs need Rust 1.89 or newer.
- Telemetry is on by default. Turn it off with `agentpay telemetry disable`, `AGENTPAY_TELEMETRY=0`, or `DO_NOT_TRACK=1`.
- A sponsored Tempo open or top-up that waits more than about 25 seconds for manual approval expires and must be rerun.
